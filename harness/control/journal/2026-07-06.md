## NEXO-0022 - Dual Token Auth (Access 15min + Refresh 7d)

- Decision: replace single 8h JWT with dual-token scheme: access (15min) + refresh (7d).
- Decision: access tokens carry `{ sub, email, role, type: "access" }`; refresh tokens carry `{ sub, type: "refresh", jti }` (no email/role for freshness on refresh).
- Decision: use two separate Passport strategies (`"jwt"` and `"jwt-refresh"`) with `type` claim enforcement to prevent token confusion.
- Decision: use two `JwtService` instances: default for access (15min), custom `REFRESH_JWT_SERVICE` for refresh (7d).
- Work completed: updated `SessionTokenSigner` interface with `signAccessToken`, `signRefreshToken`, `verifyAccessToken`, `verifyRefreshToken`.
- Work completed: updated `IdentityProvider` with `refreshAccessToken()` + `refreshToken` in `AuthSession`.
- Work completed: implemented `JwtSessionTokenSigner` with two JwtServices and typed payloads.
- Work completed: created `JwtAccessStrategy` (validates `type=access`) and `JwtRefreshStrategy` (validates `type=refresh`).
- Work completed: updated login to set both `nexo_access_token` and `nexo_refresh_token` httpOnly cookies.
- Work completed: added `POST /auth/refresh` endpoint with `RefreshAuthGuard`.
- Work completed: updated logout to clear both cookies.
- Work completed: added `ACCESS_TOKEN_TTL_SECONDS=900` and `REFRESH_TOKEN_TTL_SECONDS=604800` env vars.

## NEXO-0023 - Security Logging Analysis

- Decision: implement security logging in 3 tiers (files → DB buffer → email alerts), NOT log everything to DB.
- Decision: use Winston + winston-daily-rotate-file for all events (Nivel 1), PostgreSQL batch for security/business events (Nivel 2), email alerts for critical patterns (Nivel 3).
- Decision: estimated ~4,500 DB rows/month (well within free tier limits). 95% of volume goes to files.
- Decision: use in-memory buffer with flush every 5 min or 50 events to minimize DB connections.
- Decision: email via Nodemailer + Gmail SMTP or SendGrid free tier (100/day). Rate-limit alerts to 1 per type every 30 min.
- Analysis completed: free tier DB limits analyzed (Neon, Supabase, PlanetScale, Railway). Volume estimates for Nexo's small internal app (~2-5 users, ~500 requests/day). Zero risk of exhausting free tiers with proposed architecture.
