# nexo-requirements-trace

## Purpose

Keep requirements, stories, acceptance criteria, and verification traceable.

## Inputs

- `NEXO_PROJECT.md`
- `docs/spec/SRS.md`
- `docs/spec/user-stories.md`
- `docs/spec/traceability.md`
- Current task plan and handoff.

## Steps

1. Identify source product statement or user request.
2. Assign or update requirement IDs.
3. Add priority, rationale, acceptance criteria, and open questions.
4. Link requirements to stories and future verification.
5. Record trace changes in the active report or journal.

## Quality Bar

No requirement should be implemented without a source, acceptance criteria, and
traceability path unless the user explicitly asks for a throwaway prototype.
