## Declaración

Los administradores deben poder gestionar los catálogos del sistema (tiendas,
categorías, marcas, tallas, métodos de pago, tipos de gasto) y los datos
operativos para asegurar captura consistente y reportes precisos.

## Racional

Sin catálogos controlados, cada operador capturaría datos libres, imposibilitando
filtros consistentes, reportes agrupados y análisis futuro.

## Criterio de Aceptación

- Dado que soy un administrador,
  cuando accedo a la sección de catálogos,
  entonces puedo crear, editar y desactivar tiendas, categorías, marcas, tallas,
  métodos de pago y tipos de gasto.

- Dado que desactivo un valor de catálogo,
  cuando los operadores usan los selectores,
  entonces el valor desactivado no aparece, pero los datos históricos que lo
  usan se preservan.

## Método de Verificación

- [ ] Demo: CRUD completo de cada catálogo desde la UI de administración.
- [ ] Prueba de integración: desactivación no rompe datos históricos.

## Artefactos de implementación

### Backend
- Módulo NestJS: `back/src/modules/catalogs/`
  - `domain/` — entidades de dominio
  - `application/` — servicios de catálogo
  - `infrastructure/repositories/` — repositorios Prisma
  - `interface/http/` — controladores REST
  - `interface/http/dto/` — DTOs de entrada/salida

### Frontend
- Feature: `front/src/features/catalogs/`
  - `views/CatalogsPage.tsx` — página principal
  - `components/CatalogEntityView.tsx` — vista genérica de entidad
  - `components/CatalogFormDialog.tsx` — diálogo de creación/edición
  - `components/CatalogDataTable.tsx` — tabla de datos
  - `config/registry.ts` — registro de catálogos
  - `services/catalog-service.ts` — llamadas API
  - `types/` — tipos por entidad (brand.ts, store.ts, etc.)
  - `store/catalog-ui-store.ts` — estado de UI

### Prisma
- Modelos en `back/prisma/schema.prisma`: `Store`, `Brand`, `Category`, `Size`, `Condition`, `Color`, `PaymentMethod`, `ExpenseType`, `DifferenceReason`, `ClothingSection`, `ClothingType`
